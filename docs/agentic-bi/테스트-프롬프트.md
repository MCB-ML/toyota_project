# Agentic BI 테스트 프롬프트

브라우저(`http://localhost:5173/ktws/agentic-bi`)에서 직접 확인할 때 쓰는 목록.

자동 검증은 `npm run llm:check`(인-프로세스) / `npm run llm:check:http`(실행 중인 dev 서버)가
경로·값·grain·일관성을 봐 준다. 이 문서는 **자동 검증이 못 보는 것** — 화면에 실제로 어떻게
그려지는지, 후속 대화가 이어지는지 — 를 눈으로 확인하기 위한 것이다.

## 읽는 법

- **기댓값**은 2026-08-03 기준이다. 웨어하우스가 다시 적재되면 숫자가 움직인다
  (예: 계약 실적이 1,532 → 1,521로 바뀐 적이 있고, BI도 함께 움직였다).
  숫자가 달라졌으면 먼저 BI 화면과 대조할 것 — 둘이 같이 움직였으면 데이터 갱신이다.
- **BI 확인** 표시가 붙은 값은 Power BI 화면과 대조해 일치를 확인한 값이다.
- BI 1-2 페이지는 브랜드 필터에 TOYOTA·LEXUS를 모두 체크한 상태를 기준으로 한다.

## 6. 퍼널 차트·표 — 계약 목표가 8배로 나오면 안 된다

| 프롬프트 | 기댓값 |
|---|---|
| `2026년 4월 퍼널 구조 차트로 보여줘` | 채널(관계형성/SC활동/내방·내전/온라인) 단계별 |
| `2026년 4월 퍼널 요약 표 보여줘` | 렉서스 강남 활동 7,242 · 기회 1,351 · 계약 264 (BI 확인) |
| `2026년 4월 퍼널 단계별 차트 보여줘` | 활동 → 기회 → 시승 → 계약 |

> 렉서스 강남 **계약 목표가 586이어야** 한다. 4,688이면 상세 행을 합산한 것이다(활동유형 8종 × 586).

## 7. 후속 수정 — 앞의 표를 이어서 고치기

**5번의 표를 먼저 만든 뒤** 이어서 물을 것. 새 표가 만들어지면 안 되고 기존 표가 바뀌어야 한다.

| 프롬프트 | 기댓값 |
|---|---|
| `2026년 4월 활동 목표 현황 보여줘` | 월 목표 관리 표(126행) |
| ↳ `여기서 활동유형 컬럼은 지워줘` | 같은 표가 갱신, 활동유형 열 사라짐, 125행 + 합계 |
| ↳ `딜러 단위로만 보여줘` | 16행 + 합계 |
| ↳ `여기서 모델 컬럼 빼줘` | "이 표에 없는 컬럼입니다: 모델" |
| ↳ `이거 막대그래프로 바꿔줘` | 겉모습만 바뀜(데이터 재조회 없음) |

| `2026년 4월 시승 포함해서 퍼널 전체 지표 보여줘. SC별로.` | 행이 많다며 묶을 단위를 되물음 |

## 9. 필터 — 이름에 공백이 있는 값

`토요타 동대문`은 데이터에 `'토요타 동대문 '`(끝 공백)으로 들어가 있다.
예전에는 이 필터가 오류 없이 **0건**이 됐다.

| 프롬프트 | 기댓값 |
|---|---|
| `2026년 4월 15일 토요타 동대문 전시장 활동 진행 현황 보여줘` | 171행(0건이면 결함) |
| `2026년 4월 토요타 동대문 전시장 목표 관리 보여줘` | 2행 |
| `동대문 전시장 2026년 4월 활동 진행 현황` | 171행 — 브랜드를 떼도 찾아낸다 |
| `강남 2026년 4월 목표 관리 보여줘` | 렉서스/토요타 중 어느 강남인지 되물을 수 있다 |

> 원인이 세 겹이었다. SQL의 LIKE 패딩이 끝 공백을 못 넘긴 것, LLM이 `"토요타 동대문"`을
> `"동대문"`으로 줄여 보낸 것, 그리고 서버에 이름을 맞춰 주는 장치가 없던 것.
> 셋 다 고쳤다 — SQL은 `LTRIM(RTRIM())`, 프롬프트에 전시장명 규칙, 그리고
> 실제 값 목록과 대조하는 해석기(후보가 여럿이면 되묻는다).

> 같은 성격의 값이 SC 36명·팀 7종에도 있다. 진단은
> `../../../notebook/05_차원이름_공백_진단.ipynb` 참고.

## 10. 폴백 — 파생으로 답할 수 없는 요청

GOLD는 한 달치를 계산하는 구조라 여러 달·다른 축은 기존 지표 경로로 가야 한다.
**틀린 답을 내는 것보다 다른 경로로 가는 게 맞다.**

| 프롬프트 | 기댓값 |
|---|---|
| `2026년 월별 활동실적 추이` | 기존 경로(여러 달) |
| `2026년 4월 모델별 출고 대수 보여줘` | GOLD에 없는 축 |
| `2026년 1분기 활동실적 알려줘` | 50,449 — 아래 월별 합과 같아야 한다 |

월별 활동실적(교차 검산용): 1월 11,150 · 2월 13,502 · 3월 25,797 · 4월 47,718.
1분기 합이 50,449로 맞는다. GOLD 파생과 기존 경로가 이 네 달에서 같은 값을 낸다 —
경로가 갈려도 숫자가 갈리지 않아야 한다.

## 11. 눈으로만 확인되는 것

자동 검증이 못 보는 부분이다. 화면을 직접 볼 것.

- 차트가 실제로 그려지는가(막대·선이 보이는가, 빈 프레임이 아닌가)
- 축 라벨·범례·색이 맞는가
- 표가 길 때 스크롤이 되는가
- 위젯을 저장했다가 페이지를 새로고침하면 같은 값이 다시 나오는가
- 퍼널 피라미드 표의 **채널 값은 BI에서 그 채널 버튼을 눌렀을 때와 같은 숫자**다
  (2026-08-04부터). BI 1-1 상단 버튼으로 대조할 수 있다 — 예: 자사출고+타사출고를
  Ctrl로 함께 선택하면 관계형성활동 채널 값이 나온다.
- **채널 합과 단계 합계는 여전히 다를 수 있다.** 한 리드가 여러 활동유형에 걸치고 단계
  사이를 이동하기 때문이며, BI도 같은 성질이라 결함이 아니다.
  2026-04 기준 기회 3곳(최대 11건) / 시승 7곳(최대 5건).

## 12. 알려진 약점

결정이 필요한 미해결 건은 [알려진-이슈.md](알려진-이슈.md)에 근거와 함께 정리돼 있다.
특히 **계약 진행률은 BI 안에서도 카드(35%)와 표(48%)가 다르다** — 어느 쪽이 나와도
지금은 결함이 아니다.

고치지 않은 채 남아 있는 것들. 여기 걸리면 새 결함이 아니다.

- **드물게 조회가 0을 돌려준다.** 동시 조회(15개 병렬)를 반복하다 한 라운드에서 관찰했고
  결정적으로 재현되지는 않는다. Fabric 쪽 일시 현상으로 보여 우리가 없앨 수는 없다.
  대신 퍼널 프리셋은 **합계 행과 대조해 어긋나는 값은 쓰지 않고** 그 사실을 알린다
  ("일부 값이 합계와 맞지 않아 보정하지 않았습니다"). 그 메시지가 보이면 다시 물어볼 것.
- **피라미드 채널 값은 근사치다** (위 11절 참고). 단계 합계는 정확하다.
- **"목표"처럼 대상이 빠진 질문**은 되묻는다 — 답을 바로 원하면 대상을 붙여 물을 것.
